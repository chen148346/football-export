## 1. 项目概述

### 1.1 项目背景

本系统是一个足球比赛数据采集与分析平台，从球探网（titan007.com）抓取比赛数据，包括比赛基本信息、技术统计、重要事件、球员数据、交锋历史、近期战绩等。系统通过 scraper.py 抓取两个核心页面：ShiJian页面（实时事件加技术统计）和 Analysis 页面（近期比赛加分析数据），分别存储到数据库的 shijian_json 和 analysis_json 字段。

本模块为独立的数据报表导出模块，将 JSON 数据解析并导出为结构化的 Excel 文件，用于机器学习训练与数据分析。

### 1.2 模块定位

- **职责范围**：独立开发数据报表导出模块，与系统开发人员的代码完全解耦
- **访问模式**：以**只读**权限访问数据库，不修改任何数据
- **核心功能**：按筛选条件从数据库读取比赛数据，生成包含 12 个 Sheet 的结构化 Excel 文件
- **不涉及**：数据抓取、存储和管理功能，仅负责数据导出

### 1.3 项目目标

- 支持日期范围筛选（开始日期至结束日期，精确到分钟）
- 支持联赛类型多选筛选
- 支持球队名称精确搜索
- 仅导出完场比赛（`latest_state_code = -1`）
- 支持非完场快照导出（半场/自定义分钟区间）
- 支持按球队拆分导出，每支球队生成独立文件
- 导出格式为包含 12 个 Sheet 的 Excel 文件
- 处理 JSON 嵌套结构、多语言字典、动态列、Odds 字段过滤等技术难点

## 5. 配置文件

编辑 `config.ini` 设置数据库路径和导出目录（留空则自动检测）：

```ini
[paths]
db_path =                    # 留空自动查找 football.db 或 upload/*.db
output_dir =                 # 留空默认使用 download/
```

### 路径检测规则

1. 优先使用 `config.ini` 中指定的路径
2. 若指定路径不存在，自动降级到默认路径
3. 默认在项目目录下查找 `football.db` 或 `upload/*.db`
4. 输出目录若不存在则自动创建

### 跨平台兼容

- 所有路径基于模块所在目录的相对路径计算
- 使用 `os.path.join` 拼接路径，避免硬编码分隔符
- 支持 Linux 和 Windows 双平台
- 系统目录黑名单同时覆盖 Linux（`/`、`/root` 等）和 Windows（`C:\`、`D:\` 等）

### 6.2 Sheet 详细说明

#### 6.2.1 match_overview - 比赛总览

每行一场比赛，包含比赛基本信息、比分、排名、阵型、角球、红黄牌等 29 个字段。数据来源为 matches 表（数据库字段）补充 shijian_json 的阵型和角球信息以及 analysis_json 的裁判信息。

**关键字段**：`match_id`、`sclass_name`、`match_date`、`match_time`、`home_team`、`away_team`、`home_score`、`away_score`、`home_rank`、`away_rank`、`home_formation`、`away_formation`、`referee_name` 等。

**V1.5 变更**：比分字段分离为 `current_home_score`/`current_away_score`（特征列）和 `label_home_score`/`label_away_score`（标签列），原始 `home_score`/`away_score` 字段保留。

#### 6.2.2 tech_stats - 技术统计（动态列）

每行一场比赛，使用动态列设计。固定列包括 `match_id`、`sclass_name`、`home_team`、`away_team`。动态列根据所有比赛的 techStat.itemList 的 kind 并集生成，格式为 `home_{kind}_{中文名}` 和 `away_{kind}_{中文名}`。

**常见统计项**：角球、射门、射正、控球率、传球、传球成功率、铲球、过人、预期进球(xG) 等约53项。

**V1.5 变更**：百分比字段（如传球成功率）从 `76%` 格式转为 `0.76` 浮点数，覆盖 8 种百分比 kind。

#### 6.2.3 events - 重要事件

每行一个事件，包含 12 个字段：`match_id`、`event_index`、`time`、`side`、`process`、`event_type`、`player_name`、`player_id`、`related_player`、`home_score`、`away_score`、`extra_info`。

**事件类型**：进球(goalIn)、黄牌(yellowCard)、红牌(redCard)、换人(changePlayer)、视频裁判(videoReferee)、点球(penaltyKick)、比赛节点(matchProcess) 等。

#### 6.2.4 player_stats - 球员统计（动态列）

每行一名球员，使用动态列设计。固定列包括 `match_id`、`team_side`、`team_name`、`formation`、`player_id`、`player_name`、`player_num`、`is_best`。动态列根据所有球员的 techInfos 的 infoKind 并集生成，格式为 `tech_{infoKind}`。

**常见技术指标**：Shots、PassBall、Fouls、PassSucceeRatio、PlayingTime、Position、Ranking 等约28项。百分比数据自动转为 0~1 浮点数。

#### 6.2.5 near_matches - 近期战绩

每行一场近期比赛，包含 27 个字段。数据来源为 analysis_json.nearMatches.homeMatches.matches 和 awayMatches.matches。包含 `near_match_id`、`league_name`、`match_time`、主客队名称、比分、半场比分、角球、红黄牌、是否先进球、射正等。`match_time` 为 10 位 Unix 时间戳，自动转换为北京时间。

#### 6.2.6 vs_matches - 交锋历史

每行一场交锋记录，包含 25 个字段。数据来源为 analysis_json.vsMatches.matches。结构类似 near_matches，但不含 `team_side` 和 `team_name` 列（交锋是两队共同历史）。注意只提取 matches，不提取 matches2（赔率相关）。

#### 6.2.7 goal_distribution - 进失球分布

每行一场比赛 × count_type × 球队，共 15 个字段。数据来源为 shijian_json.jsq.jsqList。包含 `match_id`、`count_type`（Count_30 或 Count_50）、`team_side`（home 或 away），以及 6 个时间段的进球率(JQ)和失球率(SQ)：1-15、16-30、31-45、46-60、61-75、76-90 分钟。百分比数据自动转为浮点数。

#### 6.2.8 first_half_tech_stats / second_half_tech_stats - 上下半场技术统计

动态列设计，结构与 tech_stats 一致，但数据分别来自上半场（`half=1`）和下半场（`half=2`）的半场技术统计快照。数据来源为 snapshots 表中的 shijian_json 的 ht_stat 数据。

#### 6.2.9 league_rank_stats - 联赛排名统计

每行一场比赛 × 球队，包含联赛排名相关数据。数据来源为 analysis_json 中的联赛排名信息。`GoalAvg` 和 `LossAvg` 字段转换为浮点数，其余数字字段转换为整数。

#### 6.2.10 half_full_stats - 半全场统计

每行一场比赛，包含半场和全场的结果对比统计。数据来源为 shijian_json 中的 half_full 数据。当 `allhalf` 为 None 时，返回空列表（不报错）。

#### 6.2.11 detailed_events - 详细事件

每行一个事件，包含事件的时间流描述和过程信息。数据来源为分析结果中的详情事件列表。事件列表按时间顺序排列，使用 `reversed(lives)` 反转逻辑确保事件顺序正确（首条为 Start）。

## 7. 数据筛选规则

模块支持以下筛选条件，均可选组合使用：

| 筛选条件 | 字段 | 匹配方式 | 说明 |
|----------|------|----------|------|
| 日期范围 | `match_date` + `match_time` | 字符串比较 | 支持精确到分钟，V1.6 新增 `start_datetime`/`end_datetime` 参数 |
| 联赛筛选 | `sclass_name` | 精确匹配（IN 查询） | 支持多选 |
| 球队筛选 | `home_team` / `away_team` | 精确匹配（= 查询） | V1.6 由模糊搜索改为精确搜索 |
| 比赛状态 | `latest_state_code` | = -1（完场） | 仅导出完场比赛 |
| 快照完整 | `fulltime_snapshot_id` | IS NOT NULL | 确保有完整 JSON 快照 |
| 导出数量 | - | LIMIT 控制 | 可设置每场 / 每队最大导出数量 |

### 日期时间筛选（V1.6+）

- 前端使用 `datetime-local` 输入框，精确到分钟
- 支持三种快捷按钮：今天、最近一个月、全部
- 后端同时接收 `date_start`/`date_end`（纯日期字符串）和 `start_datetime`/`end_datetime`（完整时间字符串）
- 优先使用 `match_time` 字段（YYYYMMDDHHMMSS，14位数字）做精确到分钟的筛选

### 按球队拆分导出（V1.6+）

- 勾选"所有球队"后，系统按球队维度将比赛分组
- 每支球队生成一个独立 Excel 文件
- 文件名格式：`{球队名称}_yyyymmdd.xlsx`
- 文件名非法字符自动替换（`/ \ : * ? " < > |` → `_`）

### 每队比赛数量上限（V1.7+）

- 在"所有球队"复选框旁可设置"比赛数量"（默认 10）
- 按 `match_time` 降序排列，取距离截止日期最近的 N 场比赛
- 不足 N 场则有多少导多少
- 空值或 ≤ 0 则不限制

### 子目录保存（V1.7+）

- 按球队拆分导出时，文件保存在 `{输出目录}/{联赛名称}_{yymmdd}_{yymmdd}/` 子目录下
- 单选联赛 → 使用联赛名作为目录名
- 多选/未选联赛 → 使用 `multi` 作为目录名
- 日期为空 → 使用 `000000` 占位
- 非法字符自动替换

### 8.2 导出流程

```
用户填写筛选条件 → 点击"开始导出"
  → 前端 POST 请求到 /api/export_excel
  → 后端启动后台线程执行导出
  → 返回 task_id
  → 前端轮询 /api/export_status/{task_id}
  → 导出完成后显示下载链接
```

### 8.3 非完场模式（V1.5）

Web 页面提供三种比赛模式选择：

| 模式 | 说明 | 导出文件 |
|------|------|----------|
| 完场（默认） | 导出完整的全场比赛数据 | 单文件 |
| 半场 | 仅导出上半场（45分钟）的快照数据 | 两个文件：prediction_xxx.xlsx + label_xxx.xlsx |
| 自定义区间 | 导出指定分钟区间（如 30-70分钟）的快照数据，可勾选是否包含完场数据 | 两个文件：prediction_xxx.xlsx + label_xxx.xlsx |

**V1.5 非完场模式的特殊规则**：
- 非完场模式下，`prediction` 文件使用比赛当前时刻前（含该时刻）的数据，`label` 文件使用完场数据
- 文件名格式：`{timestamp}_{league}_{date}_{type}_{prediction/label}_{fields}.xlsx`
- 比分字段分离：`current_home/away_score`（特征）和 `label_home/away_score`（标签）

- 支持半场模式：仅导出上半场（45分钟）的快照数据
- 支持自定义分钟区间：导出指定分钟区间（如 30-70分钟）的快照数据
- 可勾选是否包含完场数据（仅自定义模式下）
- 非完场模式下生成两个文件：`prediction`（特征）和 `label`（标签）

#### 9.5.2 文件命名规范升级

文件名格式：`{timestamp}_{league}_{match_date}_{type}_{prediction/label}_{fields}.xlsx`

示例：
- `2607140900_英超_20260714_FT_all.xlsx`（完场，全字段）
- `2607140900_英超_20260714_PRED_all.xlsx`（非完场，prediction）
- `2607140900_英超_20260714_LABEL_all.xlsx`（非完场，label）

#### 9.5.3 比分字段分离

- `current_home_score` / `current_away_score`：特征列（当前时刻比分）
- `label_home_score` / `label_away_score`：标签列（完场比分）
- 原始 `home_score` / `away_score` 字段保留

#### 9.5.4 百分比字段小数化

- 扩展百分比 kind 集合至 8 项：`PassSucceeRatio`、`StealProb`、`Controls`、`ShootProb`、`StealSuccessRatio`、`PassSuccessRatio`、`FoulsProb`、`FoulsSuccessRatio`
- 所有百分比值从 `76%` 格式转为 `0.76` 浮点数

#### 9.5.5 数据字典枚举值规范化

- 优化事件类型、比赛状态等枚举值的统一映射
- 确保 `player_stats` 和 `tech_stats` 的 kind 名称一致

### 9.6 V1.6 - 日期时间精确 + 按球队拆分

#### 9.6.1 日期时间精确到分钟

- 日期选择器从 `type="date"` 升级为 `type="datetime-local"`
- 默认值：开始时间 = 当日 00:00，截止时间 = 当日 23:59
- 后端同时接收 `date_start`/`date_end`（纯日期）和 `start_datetime`/`end_datetime`（完整时间）
- 使用 `match_time` 字段（YYYYMMDDHHMMSS）做精确到分钟的筛选

#### 9.6.2 按球队拆分导出

- 新增"所有球队"勾选框
- 勾选后，系统将所选联赛范围内的所有比赛按球队维度拆分
- 每支球队生成一个独立 Excel 文件
- 文件名格式：`{球队名称}_yyyymmdd.xlsx`
- 非法字符自动替换

#### 9.6.3 球队搜索改为精确匹配

- 前端提示从"模糊搜索"改为"精确搜索"
- SQL 查询从 `LIKE` 改为 `=` 精确匹配

### 9.7 V1.7 - 子目录保存 + 比赛数量上限

#### 9.7.1 按联赛+日期范围创建子目录

- 按球队拆分导出时，文件保存在子目录下
- 子目录命名规则：`{联赛名称}_{yymmdd}_{yymmdd}`
- 单选联赛 → 使用联赛名
- 多选/未选联赛 → 使用 `multi`
- 日期为空 → 使用 `000000`
- 非法字符自动替换

示例：
```
download/
├── 瑞典超_260726_260727/
│   ├── 哈马比_20260803.xlsx
│   └── 佐加顿斯_20260803.xlsx
└── multi_260701_260715/
    ├── 富川FC_20260803.xlsx
    └── 挪威_20260803.xlsx
```

#### 9.7.2 每队比赛数量上限

- 在"所有球队"复选框旁新增"比赛数量"输入框
- 默认值：10，可修改
- 按 `match_time` 降序排列，取距离截止日期最近的 N 场比赛
- 不足 N 场则有多少导多少
- 空值或 ≤ 0 则不限制
- 仅勾选"所有球队"时该字段生效

#### 问题1：query_matches LEFT JOIN 语义优化

**问题分析**：SQL 查询使用 `LEFT JOIN snapshots` 并在 `WHERE` 子句中添加 `snapshots.id IS NOT NULL` 条件，实际上将 `LEFT JOIN` 退化成了 `INNER JOIN`。
